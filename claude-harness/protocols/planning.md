# Protocol · Planning

> Layer 1 — universal per-task procedure. No project specifics.

Use when the task needs a plan before action (multi-step work, anything with
trade-offs or irreversible steps).

## Steps
1. **Frame the goal.** State the outcome in one sentence. Note the constraints
   (time, compatibility, things that must not break).
2. **Gather context.** Read the relevant material first. Find existing patterns,
   utilities, and prior art to reuse before proposing anything new.
3. **Surface decisions.** List the real forks. For each, give the options and a
   recommendation with a reason. Ask the user only about the ones that are genuinely
   theirs to decide.
4. **Sequence the work.** Order steps so each is verifiable and the risky/irreversible
   ones come after cheap checks.
5. **Name verification.** Say how you'll know it worked, end-to-end.

## Output
- When scope itself is unclear or contested, align on it first with
  `templates/task_brief.md`; otherwise go straight to the plan.
- Use `templates/plan.md`.
- Recommended approach only — not a catalog of every alternative considered.
- Name the specific files/areas to change; for repeated patterns, describe once and
  list a few representative targets.

## Don'ts
- Don't plan past what you understand — if a step is fuzzy, that's a research item,
  not a plan item.
- Don't over-decompose trivial work into ceremony.
